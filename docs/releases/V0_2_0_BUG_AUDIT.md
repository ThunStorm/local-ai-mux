# LocalAiMux v0.2.0 隐性问题检查

日期：2026-10-26。范围覆盖限时、异步设置、Gateway流/非流、HTTP/CLI边界、正文存储、导出、权限/续接与升级兼容。检查采用源码审阅、虚拟时钟、回环合成服务与文件读回，不发真实模型请求。结果不代表全平台或所有厂商均无缺陷。

## 已修复并复现验证

### BUG-01：保存结果未知时仍显示旧配置已保存

原界面仅显示错误，保留旧saved值；如果IPC在后台写入成功后传输失败，旧值与实际配置不同。初始读取也未作为忙状态保护，可能与重新读取竞争。

修复：初载即进入忙状态；读取/保存采用请求代次保护、卸载失效；任何未确认结果将saved设为未知、禁改输入与保存，只有重新读取成功后恢复。合成IPC模拟“已写入但返回失败”，确认不再误显示旧值，重新读取取得实际新值；1200保存/重载、1201拒绝及中英浅深三尺寸通过。

### BUG-02：HTTP非流式输出可绕过大小边界

原HTTP Adapter直接response.json，无有界读取；非流式Gateway也未像流式一样检查8MiB文字上限，超大结果可能先分配/解析大量内存或被当作成功返回。

修复：模型目录/公开本机元数据JSON最多4MiB，非流式响应JSON最多64MiB，在Content-Length与chunk复制前检查；正文8MiB上限由HTTP Adapter和Gateway Chat/Responses两层核对。SSE缓冲同样在扩容前检查。超限统一LMX_OUTPUT_TOO_LARGE，失败不保存超大正文、不新建成功续接映射，也不根据该错误推断供应商停服。回环声明长度/无声明chunked超限、正常小JSON、HTTP非流大文本和两端点自定义Adapter大结果均有回归。

### BUG-03：Ubuntu SDK工作流的工具链组件准备不完整

首个封版候选852037e的sdk-compat job在执行SDK测试前，由Rustup补装rustfmt时发生bin/cargo-fmt文件冲突；本机全工具链环境不会复现该准备顺序。修复使SDK、桌面打包与签名候选工作流显式准备仓库rust-toolchain.toml所需的rustfmt/clippy，与verify job一致。另将测试Python SDK基线固定3.24.0，避免封版验证随最新包变化。最终远端检查只看修复后提交，旧失败保留可追溯。

### BUG-04：Unix测试导入导致Windows Clippy失败

候选852037e的Windows verify在cargo clippy阶段发现adapter-sdk/cli.rs可靠性测试模块无条件导入StreamExt，但使用它的进程组测试受cfg(unix)保护，Windows因此触发-D unused-imports。导入现加同样cfg(unix)，不禁用警告、不跳过Windows验证，也不改变运行时代码。该类跨平台问题不能由macOS Clippy通过推定不存在；最终结果以修复后Windows job为准。

### BUG-05：实时时序测试在CI高负载下误超时

macOS候选f22daf4在CLI空闲重置测试中，Shell启动/调度与150ms实际sleep共用250ms余量，高负载时成功分支误触发超时。改为CLI与Codex共用的有界事件读取函数，以Tokio虚拟时钟和内存管道验证：每150ms完整事件重置250ms空闲，总时长300ms仍通过，随后无事件严格250ms触发正确层。该测试现在跨平台执行；真实owned进程/父子清理/异常退出仍由独立Unix测试覆盖，没有简单放宽生产限值或删除断言。
