# 本地数据、迁移与恢复

桌面控制层启动时由 `apps/desktop/src-tauri/src/data_storage.rs` 建立数据环境，然后打开 SQLite 和初始化日志。`crates/core/src/data_paths.rs` 管理引导配置、原子保存和路径校验。`crates/telemetry/src/file_log.rs` 管理日志轮转及保留。

| 位置 | 内容 |
|---|---|
| 固定引导目录 | 由操作系统的 ProjectDirs 确定，沿用 `LocalMux`。保存 `storage.json`、单实例文件锁及本机 Key 存储锚点。Windows Key 明文由系统凭据服务保管。 |
| 当前业务数据目录 | 默认与引导目录相同。可配置，包含 `localmux.db`、人工备份、脱敏日志和占用样本。 |
| 系统和用户自选位置 | WebView 状态、缓存、CLI 临时文件及用户导出各有独立生命周期。 |

## 修改数据目录

1. 在偏好设置的“数据与日志”选择已存在的空目录并保存。应用展示当前和待生效路径；当前进程继续使用原库，可在重启前取消。目标拒绝符号链接、应用包、Git 工作区和与源目录重叠的位置。
2. 正常退出并重启后，程序先取得固定目录中的单实例锁。通过 SQLite Online Backup API 从源库生成一致快照，保留 WAL 中已提交的内容和隐式 rowid。暂存目标通过完整性及外键检查，再复制备份、日志和采样文件。
3. 发布目标目录后原子更新引导配置，随后打开新库。旧目录成为静态回退副本。本机 Key 锚点、SQLite Schema 13 和授权身份沿用原值。

## 恢复

- 自定义盘不可用时，恢复原盘后重启。缺库时启动明确失败。
- 权限、磁盘空间或校验失败时，保留源库和目标内容。目标已发布但配置提交失败时，下次启动通过准备标记复核源与目标指纹及目标库完整性，再完成切换。
- 若需放弃待生效变更且界面无法启动，完全退出应用，备份 `storage.json`、源目录和目标目录，再仅将 `pending_data_dir` 设为 `null`。已迁移成功后回退需同时保护新库新增记录和凭据身份。

轮转按活动日志 5 MiB 或 UTC 换日触发，旧日志压缩为 gzip。保留默认 14 天和 100 MiB，可设 1–90 天与 10–1024 MiB。日志策略仅处置应用自身的归档日志。正文、数据库及人工备份由用户显式管理。占用按逻辑字节统计，数据库净增需要至少一小时的观测间隔。详见[可观测性](OBSERVABILITY.md)和[数据库](DATABASE.md)。
